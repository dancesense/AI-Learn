## 语音识别方案替换：webkitSpeechRecognition → DashScope qwen3-asr-flash

### 问题
浏览器原生 `webkitSpeechRecognition` 依赖 Google 语音服务，国内被墙，点击录音报 `network` 错误。

### 解决方案
使用 DashScope（阿里云百炼）`qwen3-asr-flash` 模型，通过 OpenAI 兼容模式 API 实现语音识别。

### 后端新增
1. `WerewolfAsrService.java` — 调用 `POST https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`
   - 模型：`qwen3-asr-flash`
   - 支持 base64 Data URL 格式音频输入
   - 参数：`language=zh`, `enable_itn=true`
2. `WerewolfAsrController.java` — `POST /werewolf/live/asr`
   - 接收 `{ "audio": "data:audio/webm;base64,..." }`
   - 返回 `{ "text": "转录文本" }`

### 前端改造 (analysis.js)
- 删除 `webkitSpeechRecognition` 全部代码（initRecognition/startRecognition/stopRecognition/recognition变量）
- 删除 `currentParts`、`appendTranscript`、`currentTranscript`、`flushCurrentSegment`
- 新增 `MediaRecorder` 录音：startMediaRecorder/stopMediaRecorder
- 录音流程：点击麦克 → MediaRecorder 录音 → VAD 检测静音 → 停止录音 → 发音频给后端 ASR → 返回文本
- 新增 `isTranscribing` 标志，卡片显示"正在录音..."/"正在识别..."
- 新增 `processTranscribedText()` 处理转录文本（发言者检测、存历史、发AI分析）
- 最短录音1秒，避免噪音触发
- `callBackendAsr()` 异步发送 base64 音频给后端

### 测试结果
- 静音 WAV 发送到 ASR 接口 → 成功返回"嗯。"（模型对纯静音正常行为）
- 编译通过，服务正常启动

### SSE流式分析（核心改造）
**问题**：后端串行调3个AI（角色+发言+胜率），全部跑完才返回，前端干等
**方案**：两阶段流式输出
1. Phase 1：快速prompt流式输出自然语言分析（chatClient.stream()），前端实时显示
2. Phase 2：结构化分析（角色概率+胜率），完成后一次性发送

**后端改造**：
- `WerewolfLiveController` 新增 `POST /sessions/{id}/stream-chunks` SSE端点
  - 直接用 `HttpServletResponse` 写SSE事件（不用SseEmitter，避免UTF-8编码问题）
  - 设置 `Content-Type: text/event-stream;charset=UTF-8`
- `WerewolfLiveAnalysisService` 新增 `consumeChunkStreaming(sessionId, req, BiConsumer<eventName, jsonData>)`
  - Phase 1: `chatClient.prompt().stream().content()` → 每个 chunk 发 `event:text\ndata:...`
  - Phase 2: `analyzePlayerRoles()` + `analyzeSpeechAdvice()` + `analyzeWinRates()` → 发 `event:complete`
  - 最终发 `event:done`
- `WerewolfLiveAnalysisService` 改为注入 `ChatModel`，在 `afterPropertiesSet()` 构建 `ChatClient`
- `application.yml` 增加 `server.servlet.encoding.charset: UTF-8`
- `buildQuickAnalysisPrompt()` 自然语言分析prompt

**前端改造**：
- `consumeQueue()` 从普通 fetch+json 改为 ReadableStream 解析SSE
- 收到 `text` 事件时实时拼接并更新 `aiSummaryText.innerHTML`
- 收到 `complete` 事件时更新概率条、角色矩阵、投票建议等结构化数据
- `renderStrategyPanels()` 不再用 `data.summary` 覆盖流式文本

**踩坑**：
- SseEmitter 默认编码不支持UTF-8中文 → 改用 HttpServletResponse 手动写SSE
- ChatClient 不是Spring Bean → 改为注入ChatModel，自己build ChatClient
- 终端locale为US-ASCII时curl显示中文乱码，但数据本身UTF-8正确

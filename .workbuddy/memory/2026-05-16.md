### 调用流程变更
- **之前**：每段录音 → ASR → queue.push → consumeQueue → AI分析（次数过多）
- **之后**：
  - 每段录音 → ASR → `/speech` 保存（无AI调用）
  - 轮到我发言 → 自动触发 `/stream-chunks` AI分析（1次）
  - 点击"回合总结" → 触发 `/stream-chunks` AI总结（1次）

### 测试结果

- `/stream-chunks` 空 transcript 时正确跳过保存，基于已有发言做流式分析

## 狼人杀助手 — 点击按钮时取消之前的AI分析

**问题**：用户点击AI按钮时，如果之前有正在进行的AI分析或队列中有等待的任务，新请求会被阻塞，显示"AI分析中，队列:1"。

**修改内容**：

### 前端（analysis.js）
1. **新增 `abortController` 变量**：用于中断正在进行的 `fetch` 请求。
2. **新增 `cancelAllAiRequests()`**：
   - `abortController.abort()` 中断当前正在流式传输的 SSE 请求
   - `queue = []` 清空等待队列
   - `sending = false` 重置发送状态
3. **三个 trigger 函数**：`triggerSpeechAdvice()` / `triggerRoleAnalysis()` / `triggerRoundSummary()` 在入队新任务前，先调用 `cancelAllAiRequests()`。
4. **`consumeQueue()`**：
   - `fetch` 传入 `signal: abortController.signal`
   - `catch` 中判断 `err.name === "AbortError"`，显示"已取消之前的AI分析"而非报错
   - `finally` 中清空 `abortController`

### 行为
- 点击任意AI按钮 → 立即中断当前正在进行的流式分析 + 丢弃队列中所有等待任务 → 立即开始新的AI分析
- 不会再出现"队列阻塞"的情况
